# Port plan: Fortune Hunter C++/SDL2 -> Odin/wasm

## Decisions (made with the user, October 2026)

1. **Rendering:** software framebuffer. Odin rasterizes a 640x480 RGBA frame (tiles, 8x8 ROM font with palette colours, backgrounds, drop shadows); the page only `putImageData`s it (Murder Hobo / Kordanor's Cabal split). No WebGL.
2. **Platforms:** web only. The core is platform-free so native `odin test` covers it. No native SDL2 client for now.
3. **Pixel assets:** the page decodes the PNGs (canvas `getImageData`) and hands RGBA buffers to Odin at startup. Native tests load the same PNGs with `core:image/png`.
4. **Audio:** the core emits sound events (sfx ids, sfx volume); a Web Audio shim in the page decodes and plays the 17 wavs after the first user gesture.
5. **Content data:** `config/*.json` translated into typed Odin tables with real enums, compiled in. No runtime JSON for content. Options/statistics saves are small hand-written JSON in namespaced `localStorage` keys, every field validated on load.
6. **Fidelity:** faithful rules, balance, screens and layouts. Odd behaviour goes in `docs/QUIRKS.md`; change only when the user decides. Level generation cannot match the C++ RNG, so tests check invariants.
7. **Input:** keyboard (arrows, Esc=back, Enter=start, Space=green, Z=blue, X=yellow, C=red, `,`=previous, `.`=next; read `e.key` before `e.code`), Gamepad API (d-pad and buttons, mirroring `FortuneHunterEventHandler.cpp`), and touch (on-screen taps/swipes; an extension that must not change rules). Keep `e.key` handling per the remote-desktop gotcha.

## Layout (modelled on murder-hobo-of-splorr)

```
odin/game/        platform-free core (package game; imported as fh:game via -collection:fh=odin)
odin/platform/web/  #+build js main + page/ (index.html, platform.js, audio.js, storage.js)
odin/tests/       #+build !js tests
docs/             PORT_PLAN.md, QUIRKS.md
tools/            build.sh, test.sh, serve.sh, ship.sh
```

Core API: `core_step(core, {dt, now_ms, events}, &out)`; `Services` (storage get/set/remove, entropy, log); output = 640x480 frame, sound events, quit/dirty flags. Time and dice are arguments. Do not use `int` for values that may exceed 32 bits.

## Milestones

1. **Done (2026-10-08).** Skeleton: `tools/build.sh|serve.sh|test.sh`, wasm page shows a test frame (main menu background, font glyphs, tiles, an arrow-key marker), JS-decoded image hand-off (the core's `IMAGE_FILES` table is the single list of paths, read by the page through `platform_image_*` exports), keyboard commands, `?seed=N`/`?log=1`. Native tests load the same PNGs. Build copies assets from `FortuneHunter/FortuneHunter/assets`. The font sheet is `assets/images/font.png`: 256x256, 16x16 glyph cells (`romfont8x8.png` is unused by the C++ game).
2. **Done (2026-10-08).** Rasterizer: `raster.odin` (`Canvas` with clip rectangle, alpha blending and colour tint as SDL did, `draw_region/draw_image/draw_sprite`), `font.odin` (16x16 cells indexed by ASCII 32..127, advance 16, centred text, black drop shadow at +4,+4), `colors.odin` (the 16 CGA colours), `sprites_data.odin` (46 tile-sheet sprites, generated from `sprites.json`), `types.odin` (`Terrain_Type`, `Object_Type`, terrain/object/health-bar sprite tables). `odin/tests/fidelity_test.odin` compares all of these with the C++ game's JSON while it is still in the repo (delete or `#+build ignore` it when the original is removed). The placeholder screen is a showcase of colours, sprites, health bars, dither and clipping. Not yet done: screen layouts, the `Unexplored`/`Dither` use in the room panel (milestone 3/4); pixel comparison against `FortuneHunter/screenshots/` (those are 642x512 window captures with a title bar, so compare by eye or crop at offset 1,31).
3. **Done (2026-10-08).** Rules: `rng.odin` (splitmix64), `descriptors.odin` and `sound.odin` (the item/creature/hunter/sfx JSON as compiled-in tables), `maze.odin` (randomised Prim plus 48 loops), `generator.odin` (locks, keys, dead-end items with minibosses, loose items, zombies; every loop capped), `world.odin` (plain-value cells and objects), `game.odin` (hunter, moves, combat, items, bombs, light, score, sound queue), `room_panel.odin` (the original's room panel renderer). 48 native tests: rules scenarios, generator invariants over 150 seeds (counts, terrain, sealed dead ends, every level clearable with its keys), a scripted player that wins real levels, and descriptor fidelity against the original JSON. `core.odin` has a temporary playable preview (Enter starts a game; arrows move; Space bomb; Esc returns to the showcase; Yellow/X new game after it ends; Blue/Z changes difficulty). Quirks are in `docs/QUIRKS.md`.
4. **Done (2026-10-08).** Screens: `ui.odin` (screen and menu state enums with the original's wrap-around order), `screens.odin` (the eight screens' commands and drawing at the original's coordinates: main menu, confirm quit, in play with room and status panels, options, about, instructions, final score, statistics), `helppages_data.odin` (generated from `helppages.json`), `persist.odin` (options and statistics as validated JSON under `fh:options` / `fh:statistics`; **persistence was pulled forward from milestone 5**), web `storage.js` shim. The core's `Step_Output` already carries `sounds`, the volume and `clipboard` for milestone 5; the page copies the About URL to the clipboard. Decisions: the main menu keeps Quit; on the web, choosing Yes shows "Thanks for playing... reload" and stops the loop (a page cannot close itself). Held keys repeat, as under SDL. Default options are the shipped `options.json` (normal difficulty, SFX 64). 59 native tests.
5. **Done (2026-10-08).** Audio: `odin/platform/web/page/audio.js` decodes the 17 wavs the core lists (paths come from `SOUND_FILES` through `platform_sound_*` exports) and plays `Step_Output.sounds` at gain `sfx_volume / 128` through fresh buffer sources. Muting sends nothing. Nothing plays before the first key press or pointer press (browser autoplay rules). Checked in the browser pane: files decode, the context stays suspended until the first key, effects are counted, mute plays nothing. Not checkable here: how it sounds. (Music was implemented and then removed at the user's request; see the decision above.)
6. **Done (2026-10-08).** Gamepad and touch, all in the page (`odin/platform/web/page/input.js`; the core only sees commands). **Gamepad:** the browser's standard layout mapped like `FortuneHunterEventHandler.cpp` (A green, B red, X blue, Y yellow, bumpers previous/next, Back, Start, d-pad); one command per press, no auto-repeat, sticks ignored (as in the original), non-standard pads ignored; polled once per frame. **Touch:** on-screen d-pad (arrows repeat while held, like held keys) plus Back, A and Start, shown after the first touch, on coarse-pointer devices, or with `?touch=1`; dragging a finger on the picture walks (one arrow per 28 screen pixels). Layout checked on desktop and a 375x812 emulated phone (controls sit under the picture in portrait and in the side bars in landscape). Mapping is unit-tested under node (`tools/input_test.js`, run by `tools/test.sh`); touch and gamepad were driven in the browser pane with synthetic pointer events and a fake pad. Not tested: real fingers and a real controller. Taps on the picture itself do nothing.
7. **Done (2026-10-08).** Polish and shipping prep. **Parity:** `odin/tests/parity_test.odin` plays a scripted game natively (6000 steps: the first two thirds arrows and Green only so games get lost and restarted, the rest every command; hard difficulty) and writes a digest of every frame (full hash every fifth step, 64 sampled pixels otherwise), every sound id, clipboard text and the saved options and statistics; `tools/wasm_parity.js` plays the identical script through the built wasm under node (the native test dumps the decoded images as raw RGBA to `build/parity_images` since node cannot decode PNGs). `tools/test.sh` requires equal digests, and builds the wasm with `-o:size` so the shipping code is what is compared. Result: identical, three games finished. **Shipping:** `tools/ship.sh [--push]` (tests, `-o:size` build, zip `build/fortune-hunter-html5.zip`; pushes with butler only on `--push`) and `shippit.sh` wrapper. The butler target `thegrumpygamedev/fortune-hunter-of-splorr:html` is the user's page (confirmed). **Page material:** `ITCH_DESCRIPTION.md`, `assets/cover.png` (`tools/make_cover.py`), `assets/screenshots/*.png` (`tools/make_screenshots.py`, exact frames from the wasm under node via `tools/frame_dump.js`), a rewritten `README.md`, and a `?keys=start,down,...` page option for QA. Not done, needs the user: create the itch.io page, confirm the slug, fill in asset credits (font, sound effects, tiles: unknown), decide about the AI-use disclosure, play it on real devices, and decide when to delete the C++ source (the other ports deleted theirs after shipping; this one's tests still read its `config/` and `assets/`, so move those first).

## Decision: no music (2026-10-08)
The user dropped music completely for now. Removed: the song file and its load, the music on/off and music volume outputs, the "MUX Volume" option (the options screen now has Mute, SFX Volume and Main Menu), `muxVolume` in the saved options, and the Komiku licence question. The 4 MB OGG is not copied into the web build (it stays in the C++ folder). Muting now just means no effects are sent. To bring music back later, see git history before this change or `audio.js` in the milestone 5 notes below.

## Decisions after milestone 7 (2026-10-08)
- Itch page: https://thegrumpygamedev.itch.io/fortune-hunter-of-splorr (slug confirmed).
- Credits: art, sound effects and code are the author's own; the page says so.
- The page text discloses that the Odin port was written with Claude Code.
- Quirk decisions are in `docs/QUIRKS.md`: attack rolls 1..N, armor-absorbed hits keep the original hurt sound (a dedicated armor sound is a TODO), health bar never empty while alive, About shows a QR code instead of copying a link, Options opens on Mute, creature outlines made transparent; all other quirks kept.
- Canvas fills the window (fractional scales are drawn from a whole-number enlargement so pixels stay crisp; `?filter=nearest` forces plain nearest-neighbour).
- The C++ source stays until the port has shipped and been played.
- Not shipping yet: the user inspects the look first; push only when told.

## Notes for a possible Steam version
- Steam does not allow linking to anything but the game's Steam page. The About screen's itch.io link and QR code (and any other external link) must be removed or replaced with the Steam page before a Steam release. Also drop the Quit-on-web workaround (a native build can really quit).
